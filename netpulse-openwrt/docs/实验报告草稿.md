# 实验二：基于 OpenWrt 的网络应用程序开发

## 一、实验目的

本实验基于 OpenWrt 操作系统完成网络应用程序开发，主要目标包括：

1. 熟悉 OpenWrt 虚拟机安装、网络配置和基本 Linux 操作。
2. 使用 C 语言和 libpcap 捕获网络数据包，实现流量统计。
3. 开发 Web 前端和后端接口，实现流量监控数据可视化。
4. 通过 Web 页面配置防火墙规则，理解 Linux/OpenWrt 防火墙访问控制机制。
5. 完成程序部署、运行验证和问题排查。

## 二、实验环境

| 项目 | 内容 |
| --- | --- |
| 宿主机系统 | Windows |
| 虚拟机软件 | VMware Workstation 或兼容虚拟机 |
| OpenWrt 镜像 | openwrt-24.10.0-x86-64-generic-ext4-combined-efi.vmdk |

| 开发语言 | C、HTML、CSS、JavaScript、Shell |

## 三、系统设计

本项目命名为 NetPulse OpenWrt，整体分为三个部分：

1. C 语言后端程序 `netpulse_server`
2. Web 前端页面
3. 防火墙配置脚本 `firewall.sh`

系统运行时，C 程序启动两个主要功能：

- 后台抓包线程：通过 `pcap_open_live` 打开 OpenWrt 网络接口，使用 `pcap_dispatch` 捕获数据包，解析 IPv4/IPv6 源地址和目的地址，并统计累计流量、峰值速率和不同时间窗口的平均速率。
- HTTP 服务线程：监听 8080 端口，提供静态页面和 API 接口。前端页面周期性请求 `/api/traffic` 获取 JSON 数据，并通过表格和折线图展示。

防火墙配置模块中，前端提交协议、源地址、目的地址、端口、动作等参数。后端先进行白名单校验，再调用固定脚本 `scripts/firewall.sh`。脚本使用 nftables 在独立的 `inet netpulse` 表中新增、查看、删除或清空规则。

## 四、关键实现

### 4.1 流量捕获

程序使用 libpcap 打开指定网络接口：

```c
pcap_t *handle = pcap_open_live(device, 65535, 1, 1000, errbuf);
```

捕获到数据包后，程序根据以太网类型判断 IPv4 或 IPv6，并提取源地址和目的地址。对源地址统计发送流量，对目的地址统计接收流量。

为了计算平均速率，程序为每个 IP 保存 40 个按秒划分的桶。每秒流量写入对应桶，查询时分别汇总过去 2 秒、10 秒和 40 秒的数据并换算为 bps。

### 4.2 Web 可视化

前端使用原生 HTML、CSS、JavaScript 实现。页面每秒请求一次：

```text
GET /api/traffic
```

接口返回格式包括：

```json
{
  "interface": "br-lan",
  "timestamp": 1710000000,
  "items": [
    {
      "ip": "192.168.1.10",
      "rxBytes": 1024,
      "txBytes": 2048,
      "peakBps": 8192,
      "avg2sBps": 4096,
      "avg10sBps": 2048,
      "avg40sBps": 1024
    }
  ]
}
```

页面展示接口名、IP 数量、总流量、折线图和详细流量表格。

### 4.3 防火墙配置

防火墙模块提供以下接口：

```text
GET  /api/firewall/list
POST /api/firewall/add
POST /api/firewall/delete
POST /api/firewall/clear
```

后端进行参数校验，限制协议只能为 `all/tcp/udp/icmp`，动作只能为 `accept/reject/drop`，端口只能为 1 到 65535。脚本内部也会再次校验参数。

脚本使用 nftables 创建实验专用表：

```sh
nft add table inet netpulse
nft add chain inet netpulse input "{ type filter hook input priority -5; policy accept; }"
nft add chain inet netpulse forward "{ type filter hook forward priority -5; policy accept; }"
```

新增规则时，脚本为规则添加 `netpulse:规则ID` 注释，便于在 Web 页面中查看和删除。

## 五、实验过程

### 5.1 OpenWrt 部署

使用 OpenWrt x86-64 vmdk 镜像创建虚拟机，网络模式设置为 NAT。进入系统后通过 `ip addr` 查看地址，通过修改 `/etc/config/network` 配置静态 IP、网关和 DNS。配置完成后重启网络服务：

```sh
/etc/init.d/network restart
```

使用 `ping 223.5.5.5` 验证外网连通性。

### 5.2 程序部署

安装运行依赖：

```sh
opkg update
opkg install libpcap nftables
```

将程序上传到 `/usr/local/netpulse`，赋予执行权限：

```sh
chmod +x netpulse_server scripts/*.sh
```

启动程序：

```sh
./scripts/run_openwrt.sh br-lan 8080
```

宿主机浏览器访问：

```text
http://OpenWrt_IP:8080
```

### 5.3 流量监控验证

在 OpenWrt 中执行：

```sh
ping 223.5.5.5
opkg update
```

Web 页面可以看到流量表格出现不同 IP 地址，接收流量、发送流量、峰值速率和平均速率发生变化。

### 5.4 防火墙配置验证

在 Web 页面添加规则：

```text
协议：icmp
源地址：any
目的地址：any
动作：drop
```

添加成功后，页面展示当前 nftables 规则列表。此时在宿主机执行：

```bat
ping OpenWrt_IP
```

ping 请求无法正常返回，说明规则生效。随后点击清空实验规则，再次 ping，访问恢复正常。

## 六、问题与解决

1. OpenWrt 无法联网  
   检查虚拟机网络模式是否为 NAT，检查 `/etc/config/network` 中 IP、网关和 DNS 配置，重启网络服务。

2. 抓不到流量  
   使用 `ip addr` 确认接口名，启动程序时通过 `-i` 指定正确接口，例如 `br-lan` 或 `eth0`。

3. 防火墙脚本执行失败  
   检查是否安装 `nftables`，确认程序以 root 用户运行，并确认脚本具备执行权限。

4. 页面无法访问  
   检查程序是否监听 8080 端口，宿主机与 OpenWrt 是否互通，必要时临时关闭或调整防火墙规则。

## 八、实验总结

本实验完成了 OpenWrt 虚拟机部署、基于 libpcap 的流量捕获统计、Web 可视化页面、防火墙规则配置接口和规则生效验证。通过该实验，我进一步理解了网络数据包捕获、流量统计、HTTP 接口设计以及 Linux/OpenWrt 防火墙规则配置流程，也体会到嵌入式 Linux 环境中依赖管理和部署调试的重要性。
